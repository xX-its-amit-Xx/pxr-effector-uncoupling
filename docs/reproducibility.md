# Reproducibility guide

This document is the contract between this repository and a reviewer who wants
to re-run the analysis. Every CSV in `data/processed/` and every PNG in
`figures/` is regenerated by the scripts listed below; pinned dependencies
are in [`requirements-lock.txt`](../requirements-lock.txt) (and the byte-exact
[`uv.lock`](../uv.lock)); the resolved column-by-column meaning of every output
is in [`data_dictionary.md`](data_dictionary.md).

The CI pipeline (`.github/workflows/ci.yml`) executes the lint / test / figure
re-render path on every push and pull request and uploads the regenerated
figures as a downloadable artifact for visual diffing.

---

## 1. Environment setup

### Required

- Python `>=3.11` (CI runs 3.11; local development tested through 3.13).
- ≥ 16 GB RAM for the metacell / bootstrap / sensitivity sweep stages.
- ≥ 2 GB free disk for the cached atlas + per-stage CSVs.
- A POSIX shell (Linux / macOS / WSL) for the Census fetch step (see Stage 1 in
  §3 — TileDB-SOMA's threadpool deadlocks on musl libc, so use glibc).

### Option A — uv (recommended; matches CI exactly)

[uv](https://docs.astral.sh/uv/) handles Python interpreters, lockfiles, and
virtual environments in one tool:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh   # one-time install
uv sync --extra dev --frozen                       # installs from uv.lock
```

`--frozen` makes uv refuse to update the lock; that's what CI uses, so doing
the same locally guarantees parity. Drop `--frozen` if you intentionally want
to refresh.

### Option B — pip + requirements-lock.txt

For environments where uv is not available:

```bash
python3.11 -m venv .venv
source .venv/bin/activate                          # POSIX
# .venv\Scripts\activate                           # Windows PowerShell
python -m pip install --upgrade pip
python -m pip install -r requirements-lock.txt
python -m pip install -e .                         # install this package
```

The lock file pins every transitive dependency to the same versions in
`uv.lock`. Some lines carry environment markers
(`; platform_system == "Windows"`) so pip will silently skip platform-specific
packages where they don't apply.

### Option C — Devcontainer

The `.devcontainer/` directory provides a VS Code Dev Container that reproduces
the CI environment locally (Ubuntu 22.04 + Python 3.11 + uv pre-installed).

## 2. Data acquisition

| Source                             | Where it lives                                | How to (re-)fetch                                                                                            |
| ---------------------------------- | --------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| CELLxGENE Census `2025-01-30`      | `data/raw/nr1i2_atlas.h5ad` (≈ 40 MB)         | `gh workflow run fetch_atlas.yml` (Ubuntu glibc) or `uv run python scripts/fetch_atlas.py` locally on glibc. |
| GTEx v8 portal API                 | `data/cache/gtex_<SYMBOL>.json` (one per gene) | Fetched on first run of `scripts/run_gtex.py`; per-gene JSON cached on disk for offline replay.              |
| GEO GSE139896 (Dyavar et al. 2020) | `data/cache/GSE139896_processed.xlsx` (8.5 MB) | Already cached; original: NCBI GEO FTP `https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE139896`.       |
| iLINCS L1000 rifampicin signatures | `data/cache/lincs_LINCSCP_*.tsv` (121 files)  | Already cached; fetched by `scripts/run_lincs.py` via `pxr_uncoupling.lincs.find_signatures` + `download_signature`. |
| Open Targets Platform GraphQL      | `data/cache/opentargets_<SYMBOL>.json`         | Already cached; refreshable via `scripts/run_opentargets.py` (rate-limited; ≤ 1 req / gene).                 |

The atlas, GTEx JSON, GSE139896 spreadsheet, LINCS TSVs, and Open Targets JSON
are all read-cached: re-running any analysis script will use the local copies
without re-hitting the upstream services. Deleting a cache file forces a
re-fetch.

> **musl/Alpine caveat**: `cellxgene-census`/`tiledbsoma` deadlock on musl
> pthreads. Run `scripts/fetch_atlas.py` on glibc (e.g. GitHub Actions
> `ubuntu-latest`, the dev container, or your own Ubuntu). All downstream
> stages are pure NumPy/pandas/scipy and run on any platform.

### One-command re-render (cached path)

If `data/raw/nr1i2_atlas.h5ad` is already present, the whole pipeline reduces to:

```bash
uv run python scripts/build_provenance.py    && \
uv run python scripts/run_analysis.py        && \
uv run python scripts/run_robustness.py      && \
uv run python scripts/run_negative_control.py&& \
uv run python scripts/run_gtex.py            && \
uv run python scripts/run_geo_rifampicin.py  && \
uv run python scripts/run_lincs.py           && \
uv run python scripts/run_opentargets.py     && \
uv run python scripts/run_per_dataset.py     && \
uv run python scripts/render_supp_figures.py
```

Total cold-cache runtime: **~20–30 min** on the reference workstation.
Re-rendering only the supplementary figures from the cached CSVs (no H5AD
required) is the fastest reviewer smoke test:

```bash
uv run python scripts/render_supp_figures.py    # < 30 s
```

This is exactly what CI runs to validate every PR.

## 6. Troubleshooting

| Symptom                                                                                                   | Cause / fix                                                                                                                                              |
| --------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Segmentation fault` or hang in `fetch_atlas.py`                                                          | Running on Alpine / musl libc. Use Ubuntu (glibc), the dev container, or trigger the `fetch_atlas.yml` GitHub Actions workflow instead.                  |
| `cellxgene_census.errors.SomaConnectionError` / 403 on Census                                             | Census version `2025-01-30` is pinned in `src/pxr_uncoupling/config.py`. If CZI rotates the bucket, update `CENSUS_VERSION` to the newest stable release. |
| Repeated 429s from GTEx during cold `run_gtex.py`                                                         | GTEx API rate-limits to ~1 req/s. The script retries with `tenacity`; if you still see failures, delete `data/cache/gtex_*.json` and re-run individually. |
| `KeyError: 'NR1I2'` in `coupling.py`                                                                      | The atlas was fetched without the receptor. Re-run `fetch_atlas.py` — `NR1I2_ENSEMBL` is always prepended to the gene list by `scripts/fetch_atlas.py`.  |
| `figures/fig2*.png` missing after running `render_supp_figures.py`                                        | One of `coupling_qvalues.csv` / `coupling_ci_*.csv` / `sensitivity_agreement.csv` / `subsample_summary.csv` is missing. Re-run `run_robustness.py`.      |
| `pip install` fails on `tiledbsoma` wheels                                                                | tiledbsoma ships wheels for Linux x86_64 and macOS only. On other platforms, use uv (which has broader wheel support) or skip the fetch stage.           |
| Tests fail with `ImportError: pxr_uncoupling`                                                             | Install the package: `uv pip install -e .` (or `pip install -e .` in your venv).                                                                         |
| Ruff format/lint fails in CI but passes locally                                                           | Pin to the same ruff version as `uv.lock` (currently `0.15.12`). Run `uv run ruff format src scripts tests` and re-commit.                               |
| H5AD too large to commit                                                                                  | Intentional: `data/raw/nr1i2_atlas.h5ad` is `.gitignore`d. Use the `fetch_atlas.yml` workflow's `data/atlas` artifact branch, or re-fetch.               |

For anything not on this list, please open an issue at
<https://github.com/xX-its-amit-Xx/pxr-effector-uncoupling/issues>.
